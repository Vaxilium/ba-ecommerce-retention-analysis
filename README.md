# E-commerce Retention Analysis — Altiplano Goods (synthetic case study)

[![ci](https://github.com/Vaxilium/ba-ecommerce-retention-analysis/actions/workflows/ci.yml/badge.svg)](https://github.com/Vaxilium/ba-ecommerce-retention-analysis/actions/workflows/ci.yml)

**Business-analyst portfolio project:** a full diagnostic of why repeat purchase is falling at a
fictitious LatAm e-commerce brand — from problem framing and data quality through SQL modelling,
statistical analysis and a costed recommendation, with every artifact reproducible via `make all`.

> ⚠️ **Synthetic data.** Altiplano Goods does not exist. The dataset (79,084 orders, 20,000 customers,
> Jan 2024 – Dec 2025) is generated by seeded code and contains deliberate dirt (dupes, nulls, bad timestamps)
> so the quality pipeline has real work to do. The deliverable is the *method and decision-making*, not
> the specific numbers.

## Headline results (all computed by this pipeline)

| Finding | Evidence |
|---|---|
| 90-day repeat rate fell **35.3% → 26.8%** (-8.5 pp, -24% rel.) | `sql/32_retention_trend.sql`, cohort matrix |
| Declining repeat rate is mostly **mix shift**, not worse customers: **7.1 pp mix** vs 1.3 pp within-cell | Joint channel×discount decomposition (`sql/40`) |
| Deep discounts predict churn: heavy-discount first orders repeat at **22.4%** vs **37.4%** full-price | `sql/34_discount_effect.sql`; model OR 2.03× for "no discount" (docs/05) |
| Paid social brings volume, not loyalty: repeat **22.7%** vs referral **44.0%**; 12-month margin per customer $158 vs $256 | `sql/36`, `sql/41` |
| Colombia delivery incident: delay 1.7 → **6.4 days**, repeat 31.1% → **19.1%** | `sql/38_delay_effect.sql` |
| Churn model identifies high-repeat customers: test AUC **0.636**, top decile repeats at **1.5×** base rate | `src/model_churn.py` |
| Win-back email validated: 5.1% → 7.5% (+2.5 pp, p=0.0003), **ROI 19×** | `src/ab_test_winback.py`, `outputs/business_case.xlsx` |
| Revenue is concentrated: top decile = **53%** of revenue; champions (21% of customers) = **71%** | `sql/39`, RFM (`sql/31`) |

## How the pipeline works

```
generate_data.py  →  build_warehouse.py   →  run_sql_analysis.py  →  model_churn.py / rfm_segments.py /
(raw CSVs, seeded)   (staging → quality →     (sql/30–41, KPIs,       ab_test_winback.py / business_case.py /
                      marts, duckdb)           decomposition)          build_dashboard.py / build_roadmap.py / README
```

`make all` runs the whole chain (generate → warehouse → SQL analysis → Python analytics → docs → tests).
Seeded end-to-end: same seed ⇒ byte-identical data, same numbers in every doc.

## Method notes (honesty first)

- Duplicates, timezone-skewed timestamps and join-key nulls are injected and then **detected and repaired**
  by the SQL DQ layer (16/16 checks pass post-clean; see docs/03).
- The retention decline is decomposed with mix/rate analysis on joint cohorts, so "paid social is growing"
  doesn't get confused with "customers got worse".
- The A/B test control rate is **anchored to the measured natural reactivation rate**, not assumed;
  power analysis and CIs are computed from first principles (no scipy black box).
- The churn model is plain logistic regression with Wald CIs — chosen for interpretability, honest
  about its 0.64 AUC.
- RICE "Impact" is USD margin from measured outputs; Confidence/Effort are flagged assumptions.
